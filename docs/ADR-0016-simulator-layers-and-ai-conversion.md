# ADR-0016 设备模拟器分层与多链路（link 字段）+ 点位表 AI 转换指南

状态：已采纳（2026-11-20）　关联：ADR-0014 / FR-S1 / S3 场景

## 背景

1. 用户点位表是"主机侧采集视角"（每台设备各有 ip/port/slave，unit 常全为 1）——ADR-0013 时代
   "每 devN 一个端口"与后来"单端口按 unit 路由"都表达不了这个拓扑（unit 重复告警/端口被丢）。
2. 真实联调里有大量"串口服务器把 485 透传成 TCP"的 RTU-over-TCP 设备，模拟器只支持 Modbus TCP。
3. 用户拿到任意厂商 Excel/协议文档时，没有一条"转成模拟器可加载格式"的固定通路。

## 决策

1. **分层**：寄存器状态机（core RegSpace）与链路传输（app serve_*）解耦——`process_pdu` 为
   TCP/RTU 共用应答语义，`pump_mbap`/`pump_rtu` 各自定帧；后续 IEC104/自定义 DSL 设备只需
   新增 pump_*/应答实现，点位表与 GUI 不动。
2. **link 字段**（设备头，默认 tcp 兼容旧表）：`tcp` = Modbus TCP；`rtu_tcp` = RTU-over-TCP
   （slave+CRC 定帧，无长度域靠逐长度验 CRC 锚定帧界；未知 slave 回网关码 0x0B）。
   绑定策略不变：端口唯一→0.0.0.0（局域网直连），同端口多机→127.0.0.N。
3. **自轮询与录制双形态同样生效**（RTU 自轮询发 slave+CRC 帧、emit 剥 CRC 与解析链路口径一致）。
4. **AI 转换指南**（docs/点位表格式与AI转换指南.md）：目标格式全字段规范 + 3 个完整示例 +
   常见厂商列名映射表 + 可整段复制的转换提示词 + 人工自检清单；随发布包分发，
   配置中心「模拟联调」场景一键打开。GUI 不做转换向导（猜测规则维护成本高，AI+提示词
   已覆盖同样场景且更灵活）。
5. `open_mcp_tutorial` 泛化为 `open_doc(name)`，文档打开能力复用。

## 后果

- 真实采集表（同网关不同端口、unit 全 1）零修改加载；rtu_tcp 设备与 tcp 设备可混在同一表。
- RTU 形态端到端测试钉死 slave+CRC 应答/bit 地址注册两条语义。
- 多协议路线图：IEC 104 从机（遥信/遥测/总召唤）与自定义 DSL 设备（按 CustomSpec 定界应答）
  沿用本分层，另立任务。
- 已知边界：线圈(01)/离散量(02) 按 func3/4 bit 语义覆盖，独立线圈空间待后续。
