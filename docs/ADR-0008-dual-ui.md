# ADR-0008 双 UI 策略:egui 离线台 + Web 实时台并存

状态:已采纳(2026-11-10,决策人:项目所有者) 关联:主 spec ADR-2

## 背景

主 spec ADR-2 规定上位机为 "Rust 核心 + Web 前端 + Tauri 壳"。
当前 iotprobe 已实现 egui 桌面台(离线分析),与 ADR-2 字面不符。

## 决策

接受**双 UI 并存**,不推翻既有工作:

1. **egui 离线分析台**(现状保留):面向"拿到日志之后的复盘"——
   多格式导入、协议解析、时序曲线、异常事件、试探引擎。单二进制、无浏览器依赖。
2. **Web 实时台**(PH-1/2 按任务卡 T-1.9/T-1.10 新建):面向"现场采集"——
   报文滚动表、Canvas 曲线、过滤器、转发订阅,按冻结契约走 WS/REST。
   允许按派活须知以 mock 数据先行。
3. **解耦边界**:两 UI 共享 `iotprobe-core`(统一模型 + codec + 规则),
   核心与 UI 无反向依赖(此为 spec 3.2 的硬要求,当前结构已满足)。
   egui 台不直接接总线;采集能力落在独立 ingest 层,Web 台经 WS 消费。

## 后果

- ADR-2 的"壳用 Tauri"限定于 Web 实时台;egui 台作为补充交付物存在,
  产品对外以 Web/网关形态为主,egui 台定位"工程师离线分析工具"。
- 未来若 egui 台与 Web 台功能重叠冲突,以 Web 台为准,egui 台裁剪为纯离线 CLI+GUI 附属。
- 核心契约(frame/event schema)成为两 UI 的唯一数据交换语言,任何一方不得私改。
