# ADR-0013 配置中心整页（工作台/配置双页面 + 功能卡片布局）

状态：已采纳（2026-11-19）　关联：ADR-0008 / ADR-0012 / FR-S1 / MVP ②③

## 背景

配置入口此前散落四处：顶栏「模板管理 / 实时接入」各弹一个悬浮窗、「分析工具」菜单 4 个
checkbox 弹窗、左侧栏「协议配置」一排 +按钮、发送/104 编辑又各有窗口。每个窗口弹出位置不固定，
**当前生效状态**（挂了哪些模板/规则包、实时是否连接）要么不显示、要么要打开另一个窗口才能看到——
用户反馈"点一个弹一个，不确定打开了哪个、要到哪个去"。根因是把「要选的（配置）」和
「要展示的（状态/分析）」混在同一层交互里，且没有统一的页面概念。

## 决策

1. **顶栏页面切换**：`工作台 | 配置中心`（`App.page` 0/1）。工作台保持既有
   「左侧选信号 → 中央曲线 → 底部帧表」分析主线；配置中心整页接管中央区，侧栏与底部帧表隐藏。
2. **配置中心 = 功能卡片**：卡片（`config_card`，Frame::group 圆角框）按功能分七张：
   数据源 / 协议解析（模板） / 规则引擎 / 设备模拟器 / 实时接入与录制 / CAN 发送 / 界面与诊断；
   小卡（规则+模拟器、发送+诊断）两列并排。**卡片内部约定：上半「生效」状态展示，下半操作按钮**，
   「✔ 应用并重新加载」为统一生效入口。
3. **配置类 UI 收编进卡片**：模板管理窗口、实时接入窗口表单、设备模拟器顶栏快捷键全部迁移
   （`template_ui` / `rules_ui` / `live_form_ui` 从悬浮窗提取为可嵌入 ui 函数）；
   104 点表编辑器、发送窗口保留为窗口（前者是文档编辑形态，后者安全敏感需独立焦点）。
4. **展示类窗口不迁移**：异常事件 / 未知协议试探 / 规则任务 / 储能拓扑按 ADR-0008 保持按需悬浮窗，
   入口统一在顶栏「分析工具」菜单（菜单名显示已打开数）与配置中心「界面与诊断」卡（checkbox 同源联动）；
   顶栏「📤 发送」改 selectable_label，高亮 = 窗口开着。
5. **状态常驻可见**：顶栏保留「协议库 N 启用」与实时 ● 统计；配置中心每卡先读状态再给操作。

## 后果

- 配置一屏可见：改协议/挂规则/连实时不再需要记住"在哪个窗口"；任何配置的当前生效状态都能
  在不打开任何窗口的情况下读到。
- `show_templates` / `show_live` 字段删除，两个悬浮窗函数改为 `*_ui(&mut self, ui)` 嵌入式，
  后续新增配置项直接加卡片行，不再新增弹窗。
- 悬浮窗数量从 9 降到 5（事件/试探/任务/拓扑/发送 + 104 编辑器），全部有顶栏或卡片入口。
- 发布形态随之固化：`scripts/package_release.py` 组装
  exe + 32 位桥接 + canlib 全套硬件原料 + protocols/ DBC 库 + samples/ 示例报文 + 使用说明 为
  单目录 zip（131.9 MB），canlib 运行时 DLL（zlgcan.dll+kerneldlls、ControlCAN.dll）放搜索链直达位。
